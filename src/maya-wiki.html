What is Maya?

Maya is a standalone package manager written in bash, and is heavily inspired by ports.
It uses pre-built recipes to download, check dependencies, compile and install binaries, or in some cases (like tarballs) just install, without needing to involve compilation.
And, if removal is necessary, it also removes the binaries and all traces they leave behind.

You can find the source code for maya here.

Installation:

The Maya package manager has extremely explicit and mandatory dependencies, which are:
coreutils, gcc, git, wget, tar
First, we will clone the repository:
$ git clone https://github.com/sakaki91/maya $HOME/maya.source
After that, we will enter the directory and run the installer:
$ cd $HOME/maya.source
$ sudo ./install.sh
You must run the installer and Maya itself as root (EUID 0).

Use:

$ maya
error: -h for help

Function '-a | --about'

The '-a --about' function lists the metadata of the packages present in the /usr/local/share/maya/pkg/ directory for installation, for example:
$ maya -a make
make-4.4.1: GNU make source code.

$ maya -a discord
discord-1.0.149: All-in-one voice and text chat for gamers that's free, secure, and works on both your desktop and phone.

Function '-l | --list'

The function '-l | --list' lists all recipes contained in /usr/local/share/maya/pkg/ that are available for installation, for example:
$ maya -l
cbonsai
cmake
discord
fastfetch
[...]
There is also a filtering option within the '-l | --list' function:
$ maya -l fastfetch
fastfetch
neofetch
onefetch
pfetch

Function '-li | --list-installed'

The function '-li | --list-installed' follows the same scheme as the previous function, but filters what was installed by the maya package manager.

When installing a binary, maya creates a file in /usr/local/share/maya/pkg/info/ to serve as a way to "track" what is installed.

After installing the desired binaries, running 'maya -li' will list what was tracked here previously, for example:
$ maya -li
discord
fastfetch
make
onefetch
vault
And the "tracking" directory contains the following files:
$ ls /usr/local/share/maya/pkg/.info/
discord fastfetch make onefetch vault

Function '-cl | --clean'

When a binary is installed using Maya, Maya creates a temporary directory (/tmp/maya) precisely to "centralize" the tarballs/source-codes of the binaries.

The function '-cl | --clean' serves precisely to clean this entire folder, for example:
$ ls /tmp/maya/
example1 example2 example3

$ maya --cl
[sudo] password:

$ ls /tmp/maya
ls: could not access '/tmp/maya': File or directory does not exist

Function '-sy | --sync'

The '-sy | --sync' function is very important; it synchronizes Maya and recipes, as well as updating individual packages and all installed packages, for example:

Synchronize Maya and recipes:
maya -sy
Synchronize individual package:
maya -sy package
Synchronizes all installed packages:
maya -sy all

Function '-in | --install'

The '-in | --install' function is one of the most important functions in Maya, *obviously*.
Maya uses a philosophy and style somewhat reminiscent of FreeBSD Ports, but with an EXTREME and RELENTLESS focus on tracking orphaned packages/files during installations and removals.

And, obviously, following the style of *Ports*, the installation of binaries/programs will depend heavily on your hardware, precisely because ABSOLUTELY EVERYTHING IS COMPILED FROM SCRATCH (or almost everything), there are no ready-made repositories or binaries, only predefined recipes that Maya can read.

Below is an example of an installation:
$ maya -in pfetch
The standard pfetch recipe below is shown as an example:
$ cat /usr/local/share/maya/pkg/pfetch
#!/bin/bash

NAME="pfetch"
VERSION="0.6.0"
DESCRIPTION="A pretty system information tool written in POSIX sh."
SOURCE='https://github.com/dylanaraps/pfetch'
DEPENDENCIES=(
"git"
)

function install(){
git clone $SOURCE /tmp/maya/$NAME
/usr/bin/install /tmp/maya/$NAME/$NAME /usr/bin/$NAME
}

function remove(){
rm -rf /bin/$NAME "$MAYA_TMP/$NAME"
}
This means that ANYONE can contribute if they want, without actually needing a ready-made repository, as long as everything is filled in correctly.
If you are interested, there is a package-template.sh file in /usr/local/share/maya/src/package-template.sh

Function '-rm | --remove'

The '-rm | --remove' function is also extremely important, as it performs a RELENTLESS cleanup of ALL POSSIBLE ORPHAN FILES from the desired binary, for example:
$ maya -rm pfetch
Remember that both '-in' and '-rm' only work for files that were installed/removed by maya, as they have their own internal registry /usr/local/share/maya/pkg/.info

Uninstallation:

Removing maya is relatively straightforward because, just as I follow an extremely paranoid philosophy regarding orphaned files scattered throughout the file system, ALL of maya (if installed correctly following the Wiki) has ALL its main files centralized in /usr/local/share/maya, with a temporary directory in /tmp/maya, and a global binary in /usr/local/bin/maya.

In short, to completely remove Maya, simply run:
$ rm -rf /usr/local/share/maya /usr/local/bin/maya /tmp/maya
I STRONGLY recommend that in cases of uninstallation, you also remove the packages installed by Maya, as it will not be possible to maintain them (unless it is intentional).
